# vertx-client

Vert.x client library for Milestone Basilisk gateway and service bus.

## API surface at a glance

- `BasiliskClient.connect(vertx, config)`: registration-first connect flow (gateway register -> bus auth)
- `BasiliskClient.deregister()`: deregister current instance from the gateway
- `GatewayApiClient.registerInstanceAuto(request)`: register with generated `instanceId`
- `GatewayApiClient.registerInstance(request)`: register with explicit `instanceId`
- `GatewayApiClient.deregisterInstance(serviceId, instanceId)`: remove one instance
- `BusClient.connect(...)`: low-level authenticated bus connection
- `BusClient.subscribe(...)` / `BusClient.unsubscribe(...)`: topic subscriptions
- `BusClient.onEvent(topic, handler)`: event handler registration
- `BusClient.publish(topic, messageType, payload)` / `BusClient.publishEvent(event)`: event publishing
- `BusClient.forward(new BusClient.ForwardRequest(...))`: request/response forwarding
- `BusClient.onRequest(messageType, handler)`: register RPC-style request handlers
- `BusClient.RequestResponder.respond(...)` / `respondOk(...)`: reply to incoming requests

## Quick usage

```java
Vertx vertx = Vertx.vertx();
BasiliskClient.connect(vertx, new BasiliskClient.BasiliskClientConfig(
    "http://127.0.0.1:3000",
    "127.0.0.1",
    5090,
    "orders",
    "orders-v1",
    List.of("/api/orders"),
    "http",
    "127.0.0.1",
    7001,
    1,
    "token",
    "instance-token"
)).onSuccess(client -> {
    System.out.println("instance id: " + client.instanceId);
});
```

`BasiliskClient` owns a `gateway` client for registry operations and a `bus` client for
the TCP service bus. The top-level connect flow automatically registers the instance,
accepts the generated instance ID returned by the registry, and then opens the bus
connection using the issued token.

## Top-level API: `BasiliskClient`

### `BasiliskClient.connect(Vertx vertx, BasiliskClient.BasiliskClientConfig config)`

Creates a composed client and enforces registration-first semantics:

1. Calls gateway `/registry/register` with an empty `instance.instanceId`
2. Reads generated `instanceId` and issued `token`
3. Opens TCP bus connection and sends authenticated `CONNECT`

Returns `Future<BasiliskClient>` with:

- `client.gateway`: gateway HTTP API client
- `client.bus`: authenticated bus client
- `client.serviceId`
- `client.instanceId` (generated by gateway)

### `BasiliskClient.deregister()`

Convenience wrapper for `gateway.deregisterInstance(serviceId, instanceId)`.

### `BasiliskClient.BasiliskClientConfig`

Required constructor fields:

- `gatewayBaseUrl`: gateway base URL (for example `http://127.0.0.1:3000`)
- `busHost`, `busPort`: bus TCP endpoint
- `serviceId`, `fingerprint`, `pathPrefixes`: registration identity/routing metadata
- `scheme`, `host`, `port`, `weight`: instance network metadata
- `registrationAuthType`, `registrationToken`: registry auth credentials

## Gateway API: `GatewayApiClient`

Instantiate once:

```java
GatewayApiClient gateway = new GatewayApiClient(vertx, "http://127.0.0.1:3000");
```

### `registerInstanceAuto(JsonObject request)`

For generated identity support. This method forces:

```json
{"instance":{"instanceId":""}}
```

before sending the request to `/registry/register`.

### `registerInstance(JsonObject request)`

POST `/registry/register` and returns full JSON body.

Expected request shape:

```json
{
  "serviceId": "orders",
  "fingerprint": "orders-v1",
  "pathPrefixes": ["/api/orders"],
  "instance": {
    "instanceId": "",
    "scheme": "http",
    "host": "127.0.0.1",
    "port": 7001,
    "weight": 1
  },
  "auth": {
    "type": "token",
    "token": "instance-token"
  }
}
```

Expected response fields used by this client:

- `instanceId` (string)
- `token` (string)

### `deregisterInstance(String serviceId, String instanceId)`

DELETE `/registry/services/{serviceId}/instances/{instanceId}`.

## Service bus API: `BusClient`

The bus protocol uses newline-delimited JSON frames over TCP.

### `BusClient.connect(...)`

Opens socket and sends:

```json
{"type":"connect","serviceId":"...","instanceId":"...","token":"..."}
```

on handshake. Includes retry with backoff and socket close/exception driven reconnect.

### Subscriptions and event handlers

```java
client.bus.subscribe(List.of("orders.created"));
client.bus.onEvent("orders.created", event -> {
    System.out.println(event.encode());
});
client.bus.unsubscribe(List.of("orders.created"));
```

`onEvent("*", handler)` receives all events.

### Publishing

`publish(topic, messageType, payload)` builds a full event envelope and returns subscriber count.

`publishEvent(event)` sends a pre-built envelope as-is.

Minimal envelope fields:

- `eventId`
- `emittedAtUtc`
- `serviceId`
- `instanceId`
- `topic`
- `messageType`
- `correlationId`
- `payload`

### Forward requests

```java
client.bus.forward(new BusClient.ForwardRequest(
    "inventory",
    "inventory.reserve",
    new JsonObject().put("sku", "A-1").put("qty", 2),
    2000L
));
```

Returns `Future<JsonObject>` containing `forwardResponse` payload.

### Request responders

```java
client.bus.onRequest("inventory.reserve", (event, responder) ->
    responder.respondOk(new JsonObject().put("reserved", true)).mapEmpty()
);
```

Use:

- `responder.respond(messageType, payload)` for explicit response type
- `responder.respondOk(payload)` to mirror request message type

### `close()`

Closes the socket and stops periodic internal metrics publishing.

## Protocol compatibility notes

- Registration-first connect and generated identity flow are preserved.
- Wire framing remains newline-delimited JSON.
- Public field names in request/response envelopes remain protocol-compatible.
- Forward/request response correlation IDs are preserved by responder APIs.
